## 失敗1: コース変更で「現学年のコース表」が取れず迷走した (2026-05-22)

### 状況
学年が進級した既存生（現在高2 / 入会時小6 / 2021年入会。seitocdは伏せる）を
「国数英 週3 → 数学のみ 週1」にコース変更する作業。
正しい高2のコース（PS2･高2＝コード12100 / 単価20,220）になかなか辿り着けなかった。

### 症状
- `sks_jugyo_register` が `PS2標準コースを自動特定できません（学年=高2）` で停止。
  `available_courses` には **小6** のコース（11100:PS1･小6 / 12100:PS2･小6 …）しか出ない。
- ブラウザから直接 `IF2SHOW|{seitocd}|01|{nyujukudt}` を叩いても **小6** のコース表しか返らない。
- 通番(rowno)を 00/01/02/03、日付を 20260522 に変えて何度叩いても全部小6。

### 何をそんなに迷っていたか（誤った思考の流れ）
1. 「コース表の学年は入会日(imnyujukudt=2021)基準で決まる」と思い込んだ。
   → JSを読むと確かに `IF2SHOW|seitocd|tsuban|imnyujukudt` で imnyujukudt を渡していたので、
     「GUIでコース変更しても小6が出るはずだ」と誤結論。
2. 「コードはgrade-generic（12100=PS2で学年非依存）、価格はサーバー側で現学年から再計算される」
   という**誤った仮説に逃げた**。
   → だが当該生の現額 57,230（国数英週3）は 小6単価16,770×3=50,310 を超えるので、
     この仮説では説明がつかない（高2には固有の高い単価がある）と分かっていたのに深追いした。
3. 「別の高2在学中に入会した生徒からなら高2単価が取れる」と回り道を検討し始めた。

### 真因
**GUIの正規の操作順序を飛ばして、いきなり読み取りAPI(IF2SHOW)を叩いていた。**

SKSのコース表の学年は「入会日」ではなく「**いま編集対象にしている受講履歴行（通番tsuban）の適用日**」で決まる。
学年進級した既存生の場合：
- 入会時通番(tsuban=01)を見る → **入会時学年（小6）**のコース表
- コース変更日(2026/05/22)の履歴行を**新規に追加**して発番された**新通番(tsuban=08)**を見る
  → **適用日時点の学年（高2）**のコース表（PS2･高2=12100 / 単価20,220 が出る）

ユーザーの「追加を押して登録してから、教科を登録するんだよ」の一言が正解だった。

### 正しいやり方（GUI / AJAX 共通）
1. 受講履歴行を**先に登録**する（これが新通番を発番する）
   `IF1regist|{seitocd}|{lasttsuban}|{nyujukudt}|{適用日YYYYMMDD}|{rireki=05}|`
   → 新しい通番（例: 08）が発番される
2. その**新通番**でコース表を引く
   `IF2SHOW|{seitocd}|{新通番}|{nyujukudt}`
   → 適用日時点の学年のコース一覧＋TANKA/WGK が返る
3. コースを確定する
   `IF2ADD|{seitocd}|{新通番}|{nyujukudt}|{行}`
   行 = `{idx}:{コードcd}:{回数}:{国}:{数}:{英}:{理}:{社}:{金額}`
   例: `0:12100:1:0:1:0:0:0:20220`（PS2･高2 / 週1 / 数のみ / ¥20,220）

実測の発番列（当該生の例）:
```
IF1regist|{seitocd}|07|{nyujukudt}|20260522|05|
IF2SHOW|{seitocd}|08|{nyujukudt}          ← 新通番08で高2コース表
IF2ADD|{seitocd}|08|{nyujukudt}|0:12100:1:0:1:0:0:0:20220
```

### 教訓
1. **SKSの読み取りAPIも前段の状態（履歴行・通番）に依存する。** 状態を作らずに読むと古い/誤った結果が返る。
   「読むだけだから安全」と近道せず、人間がGUIでやる操作順序を素直に再現する。
2. 学年進級した既存生のコース変更は、**入会時通番のコース表＝入会時学年**。
   新通番を発番してはじめて現学年（適用日学年）が出る。
3. これが `sks_jugyo_register` の「PS2標準コース自動特定できません」の真因。
   → ツール改善案: rireki が 02以外（05コース変更/06選択科目変更/再登録）のときは、
     先に IF1regist で履歴行を追加→新通番を取得→その通番で IF2SHOW を引く実装にすべき。
     現状は入会時通番ベースで IF2SHOW を引くため、進級済み生で学年が合わない。
4. 仮説が現データ（当該生の57,230）と矛盾していたのに深追いした。
   **矛盾に気づいたら仮説を捨てて、正規フローの再現に戻る。**

### 確定値メモ（高2 PS2）
- コード `12100` = PS2･高2 / 単価 **20,220**
- 割引(WGK): 週1=0 / 週2=2,290 / 週3=3,430
- 検証: 20,220×3 − 3,430 = **57,230**（当該生の旧 国数英週3 と一致）
- 数学のみ週1 = 20,220×1 − 0 = **20,220**
- ※ 単価は学年・改定で変わる。常に新通番の IF2SHOW から取り直すこと（値を埋め込まない）。
